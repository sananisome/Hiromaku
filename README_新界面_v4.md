# 治幕 新界面 · v4：其它窗口一起换皮

v3 只换了主窗口。拿到完整源码后，这一版把**所有对话框**也接进了新主题：
SRT 参数、LLM 高级设置、背景设置、云端转录、免费转录、台本/专有名词编辑弹窗，
外加主窗口的拖拽遮罩、各处弹出的 QMessageBox、下拉菜单和悬浮提示。

## 怎么装

二选一，结果完全一样：

- **打补丁**（推荐，能看清每一处改动）：在项目根目录执行 `patch -p1 < 新界面-v4.patch`，或者 `git apply 新界面-v4.patch`
- **直接覆盖**：把 `src/ui/` 里的 9 个文件覆盖进项目的 `src/ui/`

`src/main.py` 不用动（你的工作区里已经是 v3 那套导入 + GBK 保护）。

## 做法

项目里的 `ui/theme.py` 本来就是「全站配色唯一来源」，各对话框都在**打开时**通过 `theme.XXX` 取颜色和样式。所以：

1. **把散落的字面量收进 `theme.py`**：各对话框里还剩下的 `rgba(255,255,255,…)`、`#FFFFFF`、`QColor(240,164,184,90)`、
   关闭按钮配色、滑块样式、拖拽遮罩颜色，全改成 `theme` 里的新令牌；标题 / 标签字体改走 `theme.title_font()` / `theme.label_font()`。
   **这些新令牌的默认值和原来的字面量逐字相同**，所以旧界面渲染不变（滑块样式经脚本比对，规则一致）。
2. **`theme_modern.install_into_legacy_theme()`**：新主窗口构建成功后，把 `ui.theme` 的全部调色板（77 个令牌，脚本核对无遗漏）和 17 个
   QSS 构建函数替换成新主题版本（函数签名逐个比对过，完全一致），再让主窗口用新主题重新生成一次自己的样式表。
   之后打开的每个对话框天然就是新皮。
3. 旧界面（`HEAL_JIMAKU_LEGACY_UI=1`）和「新界面构建失败回退」都不会调用第 2 步，原主题一字不动。

## 新主题在对话框里长什么样

- 纸面底 `#f6fafa`、16px 圆角容器；分组是白色卡片；标题用衬线粗体（深青），标签去掉描边
- 主按钮青色实心，普通按钮白底描边，危险操作（删除配置、取消上传）白底红字
- 勾选框统一成和主窗口一样的开关；单选是青色圆点；滑块细轨 + 白色把手
- 下拉 / 微调箭头改用运行时生成的灰色箭头（原来的 `*_light.png` 是给深色背景用的白箭头，浅底上看不见）
- 关闭按钮从红色圆钮改成灰色 ×，悬停才变红
- 字号统一收敛到 10–12pt（原来普遍 13–16pt）

## 改了哪些文件

| 文件 | 改动 |
|---|---|
| `theme.py` | 新增 30 个令牌（值同原字面量）+ `label_font` / `title_font` / `slider_qss` / `app_qss` |
| `theme_modern.py` | 新增新主题调色板、17 个同签名构建函数、箭头/勾图标生成、`install_into_legacy_theme()` |
| `modern_main_window.py` | 构建成功后调用一次 `install_into_legacy_theme()` 并重算主窗口样式 |
| 5 个对话框 + `main_window.py` | 只做「字面量 → 令牌」「字体 → theme 函数」替换，不动布局和逻辑 |

## 我没法替你验证的

我这边没有 PyQt6 运行环境。做过的检查：全部文件语法检查；补丁在你给的源码上 `patch --dry-run` 通过，打完后与交付文件逐字节一致；
用桩模块跑了主题层：旧主题滑块规则与原字面量一致、新主题 17 个构建函数输出的 QSS 括号配平、无 `None`、签名与原函数一致。

**没有看过任何一个对话框的真实渲染**，请重点看：

1. 每个对话框打开一次：文字是否都看得清（尤其是之前写死成白色的地方）
2. 云端转录对话框：Soniox 分组、语言列表、台本导入「锁定」态、OCR 进行中的按钮
3. LLM 设置：配置列表选中 / 当前项高亮、温度和思考模式滑块的禁用态
4. 背景设置：图片丢失时的红色输入框
5. 拖文件进主窗口时的遮罩

这次只换皮、不改布局：对话框的尺寸和排版还是原来的，字号变小后个别窗口可能显得空。哪个窗口看着别扭，截图发我，再单独调布局。
